# 上海 画面認識ヘルパー（Windows向け初期版）

ゲームの画像から牌を検出し、登録した柄の見本と自動照合するPythonアプリです。静止画の調整画面と、別ウィンドウの透明な補助表示を実装しています。ゲームのソース・DOM・通信・内部メモリを読まず、変更しません。クリックの自動実行もありません。外部認識サービスは使いません。

**ペアの自動認識は初期状態で有効です。** 柄だけでなく、牌表面の縁と、背景または露出した側面を画像で検出し、取れると判定した同グループの2枚を自動表示します。静止画・ライブとも、個別の「取れると確認」操作は不要です。

添付画像のような、明るい牌表面・灰色の厚み・色付きの側面がある描画に対応しています。曖昧な牌は保留します。絶対段数や全隠れ牌の自動復元は行いません。添付画像2配置での結果と制約は [検証結果](VALIDATION.md) を参照してください。

## 起動

通常はルートの Start-Desktop.vbs を使用します。以下のコマンドは app フォルダで実行してください。

初回は `setup.cmd` を実行します。セットアップ後は**`Start-Desktop.vbs` をダブルクリック**してください。PowerShellからも実行できます。

```powershell
.\.venv\Scripts\python.exe -m mahjong_helper
```

または `powershell -ExecutionPolicy Bypass -File .\start.ps1`。設定はルートの `json/settings.json` に保存します。別の設定を使う場合は `--config 設定ファイル.json` を指定します。

別のPCでは、Python 3.12（64bit推奨）を導入し、次を実行してください。依存ライブラリの導入時だけインターネットが必要です。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r config/requirements-tested.txt
.\.venv\Scripts\python.exe -m mahjong_helper
```

## まず合成画像で試す

```powershell
.\.venv\Scripts\python.exe -m tools.make_demo
.\.venv\Scripts\python.exe -m mahjong_helper --config examples/demo/settings.json --image examples/demo/board_0.png
```

5種類のランダム配置、重なりの曖昧な例、3種の架空の柄を生成します。デモ専用設定は単層を明示しています。実ゲームの牌・見本ではありません。デモの設定を実ゲーム用にそのまま流用しないでください。

### 添付画像でペアの自動認識を試す

```powershell
.\.venv\Scripts\python.exe -m tools.make_auto_demo
.\.venv\Scripts\python.exe -m mahjong_helper --config examples/demo-auto/five-settings.json --image examples/demo-auto/five-board.png
```

「五萬」2枚に自動で線が出ます。もう1つの配置では `south-settings.json` と `south-board.png` を指定すると「南」2枚に線が出ます。見本は各柄1枚、単層設定はfalse、手動の空き確認は0枚です。既存の `settings.json` や見本は変更しません。

## 必要な実ゲーム素材

次をまとめて提供すると調整できます。ソースコードなどは不要です。

- 異なるランダム配置の、加工・縮小していないスクリーンショット2〜3枚。
- 可能なら同じ盤面で、牌を1組取る前後の画像。
- 各柄1枚ずつの牌表面全体の見本画像。牌表面が完全に見えるスクリーンショットから、このアプリで切り出すこともできます。
- 見本の柄ID、花牌・季節牌などの特殊グループの指定。

厚みや影が見える倍率の画像があると、表面の範囲や段の描画ずれを検証できます。写真の遠近・反射補正は未実装です。

## 静止画モード

### 自動判定の使い方

画像と柄の見本を登録すると、自動で取れるペアを探します。「設定」の「画像から取れる牌とペアを自動判定する」が有効であることを確認してください。旧設定ファイルにも、項目がなければ初期値trueを適用します。

線が出ない場合は、画面上部の黄色い「ペア線」欄を確認します。「同グループの柄が2枚認識されていない」「表面の縁が欠けている」「側面の空きを画像から確認できない」などで保留します。**柄が一致するだけでは、取れるペアとして表示しません。** 複層盤面を単層の設定に変えて回避しないでください。

### 盤面の範囲と見本登録

「領域設定」→「盤面の範囲を設定」を押すと登録済みの無視領域と保有マスがすべて解除され、全体画像に戻ります。盤面の左上から右下までドラッグしてください。範囲を変更するときも同じ操作です。

「領域設定」から「無視領域を追加」または「保有マスを追加」を選び、現在の盤面上で囲みます。各種類を複数登録でき、盤面に黒枠で表示します。枠内をクリックするか画面下の「登録領域」から選び、「選択領域を削除」でその1件を削除できます。範囲は現在の盤面に対する比率で保存されます。無視領域は保有マスより優先します。保有牌は緑枠になり、保有牌を多く使う候補から順に表示します。牌をダブルクリックすると見本登録画面を開けます。牌の幅や高さは右上の歯車から調整できます。

複層では絶対段数を `?` とし、側面・表面の画像根拠だけで空きを判定します。矩形が重ならないことだけでは同じ段とは確定しません。画像だけで根拠が足りない牌は判定不明です。

表の画像座標と盤面座標は別です。画像座標を直した場合は、段数を指定し、再計算してから確認してください。手動で盤面座標を直した場合には再計算せず確認します。信頼度は類似度であり、確率・正答率ではありません。手動で柄IDを修正した場合も元の自動認識スコアを保持します。

元画像と枠付き画像は「元画像のみ」で切り替えられます。段数・上の牌・状態・理由と処理時間は表と画面下部に表示されます。通常終了時に最後に判定した盤面を設定ファイルと同じ場所の `debug/日時/` に自動保存します。board.png は元画像、annotated.png は判定枠と選択ペア線入りの画像です。設定・見本・判定結果・表示状態も一緒に保存します。書き出した修正結果の再読込は未実装です。

画面下部には「位置候補」「柄を認識した件数」「登録済み見本の柄数・枚数」を別々に表示します。枠が出ない場合は位置検出の問題、枠があって柄が不明の場合は見本未登録や照合の問題です。牌を選ぶと、最良スコア・次点スコアとしきい値も確認できます。登録画面を開くとライブ更新を一時停止し、表示中の画像が入れ替わらないようにします。

## ライブモード

1. ゲームのウィンドウを開き、対象ウィンドウ一覧で対象を選び「取得」を押します。一覧を更新するには「↻」を押します。対象はウィンドウ単位です（ブラウザのタブ単位ではありません）。ウィンドウタイトルを設定に保存しますが、次回起動時はユーザーが対象を再選択します。
2. 取得画像で「領域設定」を選び、盤面をドラッグします。ウィンドウのクライアント領域に対する比率で保存します。再設定する際はもう一度「領域設定」を押して全体から選び直します。
3. 牌サイズや見本を登録し、単層なら配置を確認したうえで `flat_board=true` に設定します。複層では `false` のままにします。
4. 「▶（開始）」を押してゲームへ戻ります。画面が安定した後に再認識します。変更のない画面では柄照合を省略し、変化を検出した時点で古い枠を消します。初期設定では400msごとに確認し、安定3フレームを必要とします。
5. **複層でもペアを自動判定します。** 牌が消えるなど画面が変わったら、古い枠を消し、安定した新しい画像から再検出・再判定します。空きの手動確認を繰り返す必要はありません。読み取れない牌だけを保留します。
6. 「⏸（一時停止）」で枠を隠します。画像の変化でも古い配置は再利用しません。

ウィンドウが最小化された場合や他のウィンドウが前面になった場合は枠を隠します。移動時は物理ピクセルで追従します。サイズ変更時は古い枠を消して取得し直します。ブラウザのズーム・DPI変更で牌のサイズや配置が変わったら、牌サイズ・ROIを調整してください。サイズ変更で牌が画面外にはみ出した場合も、盤面領域を再確認してください。

最初は取れる候補のうち、高い段の牌を含むペアを表示します。最高段が同じ場合は相方の段が高いペアを優先します。設定の「同時表示するペア数（組）」で1〜99組を指定できます（初期値1組）。「→」で次の組群に切り替わり、最後まで進むと先頭に戻ります。同じ柄が3枚以上あればすべての組合せを内部に保持します。最善手やクリア手順を求める機能はありません。線に経路制約はありません。

`Ctrl+Right` は次の候補、`Ctrl+Space` は一時停止。これらは**補助アプリ内のショートカット**です。ゲームのキー操作を横取りするグローバルキーは登録しません。

## 設定項目

「設定」で数値と単層の描画規則を変更できます。「登録した見本の一覧・編集」では柄ID・グループの修正と見本の登録解除ができます。保存形式はJSONで、空の設定例は `config/settings.example.json` にあります。設定ファイルからの相対パスは設定ファイルのあるフォルダーを基準にします。登録した見本はそのフォルダーの `templates/` にコピーします。

| 項目 | 意味 |
| --- | --- |
| `tile_width`, `tile_height` | 表面の通常の幅・高さ。取得画像の実ピクセル |
| `layer_dx`, `layer_dy` | 1段上がった際の画面上のずれ。左上なら負数 |
| `threshold` | 最良の柄スコアの下限。初期値0.78 |
| `ambiguity_margin` | 異なる柄IDの1位と2位に必要なスコア差。0.07 |
| `interval_ms` | ライブ確認間隔。400ms |
| `stable_frames` | 安定確認フレーム数。3 |
| `change_threshold` | 縮小グレー画像の平均差の上限。加えて変化ピクセル率も確認 |
| `surface_brightness` | 明るい牌表面の検出下限。155 |
| `flat_board` | 単層とユーザーが確認した描画規則。通常はfalse |
| `auto_pairs` | 表面・側面の画像根拠によるペア自動認識。初期値true |
| `roi` | クライアント領域内の `[左,上,幅,高さ]`、0〜1の比率 |
| `templates` | `{ "id": "man_1", "group": "man_1", "path": "templates/見本.png" }` の配列 |

## 認識・取得方式と限界

検出は複数の明るさで切り出した表面と閉じた輪郭から位置候補を作り、重複を整理します。明るいしきい値の画像では細い境界線をつぶさず、隣接する表面の分離を助けます。牌サイズも複数の明るさと輪郭から推定します。次に表面の中央を切り出し、縦横比を保った正規化と濃淡の勾配を使ってテンプレート照合します。近接する5サイズと小さな位置ずれを比較し、同じ柄IDの追加見本をまとめて評価します。しきい値未満や異なる柄候補が拮抗する場合、表面の存在だけを残します。

初期版の位置検出は、明るい矩形の牌を対象としています。密着して表面がつながる牌、暗い牌、部分的にしか見えない牌には検出漏れがあり、厚みを表面と誤認することもあります。全隠れ牌を補完しません。

自動判定は、通常サイズの表面と連続した明るい縁を確認し、側面の外の背景、または灰色の厚みの外にある連続した色付きの側面を検出します。色付きの側面は複数の牌から共通色を推定し、最初から緑に固定しません。単に横に並ぶ矩形だけから、同じ段の隣接・上下関係を断定しません。半分ずれた側面の遮蔽も検査します。絶対段数を復元しなくても、見えている表面・露出した側面という局所的な根拠から空き候補を出します。

この画像判定は描画依存の推定です。右下に厚みのある牌を主に想定し、別の向きの厚み・側面のない牌・白い背景・反射・小さすぎる画像では保留が増えます。縁の欠け、他候補との重なり、通常サイズからの大きな差があれば保留します。微小な遮蔽や、検出されなかった牌の重なりを完全には排除できず、すべてのゲーム描画での正答を保証しません。

全体の配置を手動補正する場合は、盤面座標・段数に基づいた従来のルール判定を使います。同じ段の左右の接触や、半マスのずれを扱います。段数不明や矛盾がある場合は保留します。

取得プロバイダーは `CaptureProvider` の形で交換可能です。初期版は対象HWNDに対する [PrintWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow) をワーカースレッドで実行します。デスクトップ全体を撮影しないため、別ウィンドウの透明枠を入力に含めません。[SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity) によるキャプチャ除外も併用します。除外の成否だけには依存しません。

ブラウザのハードウェア描画によっては黒画像・古い画像が返る場合があります。黒画像は停止しますが、古い画像が返ることを完全には検出できません。取得画像と実画面が一致するか確認してください。非対応時はスクリーンショットを静止画モードに読み込みます。PrintWindowが応答しない対象では取得やアプリ終了が待たされる可能性があります。Windows Graphics Captureの別プロバイダーやプロセス分離によるタイムアウトは今後の拡張です。

## 開発用フォルダでのテスト

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe -m tools.native_smoke
```

2つ目は実際に検証用のウィンドウを短時間表示します。ゲームは操作しません。画像のみで解析する場合:

```powershell
.\.venv\Scripts\python.exe -m mahjong_helper --config examples/demo/settings.json --analyze examples/demo/board_0.png --output examples/demo/result.json
```

## ファイル構成

- `mahjong_helper/core.py`: 設定、検出、柄照合、盤面の判定、画面安定確認。
- `mahjong_helper/visual_access.py`: 表面・露出側面・背景によるペアの自動判定。
- `mahjong_helper/capture.py`: 交換可能な取得APIとWindowsの対象ウィンドウ取得。
- `mahjong_helper/ui.py`: 静止画、修正表、ライブ制御、透明表示。
- `tools/make_demo.py`: 再現可能な合成画像の生成。
- `tests/`, `tools/native_smoke.py`: 判定・認識・調整画面・Windows表示の検証。

ライブ表示では盤面の変化を検出した後、両端の牌の画像がほぼ同じペア線を最長1.5秒引き継ぎます。牌が消えた線は取得画像の確認時に外し、新しい認識結果が届いたら表示を更新します。
